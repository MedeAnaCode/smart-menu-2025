# Первичный запуск PlanDish по IP

Этот сценарий нужен только для проверки приложения на новом сервере без домена.
Он не включает HTTPS: логин и содержимое запросов передаются по HTTP. Не
используйте его для настоящих данных и не публикуйте ссылку широко. После
проверки подключите домен и настройте HTTPS.

## Что понадобится

- Ubuntu 24.04 с установленными Docker и Docker Compose;
- каталог с исходным кодом проекта на сервере;
- открытые входящие порты `80` и `8080` в панели VDS и/или firewall.

## Настройка

В каталоге проекта на сервере создайте файл с секретами:

```bash
apt install -y nano
cp .env.server.example .env.server
nano .env.server
```

В `APP_ORIGIN` и `KEYCLOAK_PUBLIC_URL` укажите публичный IP сервера. Для
данного первого запуска это:

```dotenv
APP_ORIGIN=http://45.10.217.72
KEYCLOAK_PUBLIC_URL=http://45.10.217.72:8080
```

Замените оба пароля на разные длинные случайные значения. Их можно получить
на сервере командой `openssl rand -base64 32`. Не сохраняйте `.env.server` в
Git и не пересылайте его содержимое.

## Запуск

```bash
docker compose --env-file .env.server -f compose.server.yml config
docker compose --env-file .env.server -f compose.server.yml up -d --build
docker compose --env-file .env.server -f compose.server.yml ps
```

Первая команда только проверяет конфигурацию и не запускает контейнеры. После
старта сайт доступен по `http://45.10.217.72`, а Keycloak — по
`http://45.10.217.72:8080`. База данных и Node.js API не имеют открытых
портов на хосте: запросы `/api` и `/uploads` проходят через Nginx в контейнере
фронтенда.

## Обновление кода

После получения нового кода в каталоге проекта:

```bash
docker compose --env-file .env.server -f compose.server.yml up -d --build
```

Тома `db_data` и `uploads_data` сохраняют базу и загруженные фотографии. Не
запускайте `docker compose down -v`, если хотите сохранить эти данные.

## Важное ограничение

Keycloak в этом файле запускается в development mode, чтобы позволить временный
доступ по обычному HTTP и IP. Это осознанный временный компромисс, а не
production-конфигурация. Перед постоянным запуском нужно подключить домен,
выдать TLS-сертификат, перенести Keycloak за reverse proxy и включить его
production mode.

Временный realm `smartmenu` также допускает HTTP (`sslRequired=NONE`), иначе
Keycloak отклонит вход с публичного IP. Если realm уже был импортирован до
этого изменения, startup-import не обновит его: измените настройку один раз
через `kcadm.sh` в работающем контейнере или удалите realm только если в нём
ещё нет нужных пользователей.
