## 2. Модель данных и миграции

- Добавлены пользователи, связи сохранённых рецептов, недельные меню, списки покупок, общие ингредиенты и позиции ингредиентов рецепта.

## 3. Авторизация и доступ

- Добавлен Keycloak 26.7.0 с импортом realm и публичным SPA-клиентом.
- Frontend использует `keycloak-js`, Authorization Code Flow с PKCE и `check-sso`; токены не сохраняются в `localStorage`.
- Backend проверяет JWT через JWKS, issuer, client id и обязательный `sub`.
- В realm добавлен mapper `sub` для lightweight access token.
- Все операции с личными рецептами, коллекциями, меню и списками покупок ограничены владельцем на backend.

Проверки: TypeScript, ESLint и реальная регистрация/вход через Keycloak прошли.

## 4. Рецепты, публикация и коллекция

- Реализованы каталог, поиск, просмотр, CRUD собственных рецептов, публикация и снятие с публикации.
- Сохранение опубликованного рецепта создаёт связь с оригиналом; поддержаны удаление связи и создание нового личного рецепта на основе сохранённого.
- Добавлены общие и кастомные ингредиенты, React Hook Form + Zod на frontend и Zod на backend.
- Реализована multipart-загрузка изображений в постоянный Docker volume.
- Добавлены изменение отображаемых порций и пропорциональный расчёт без изменения рецепта.

Проверки: TypeScript и профильный ESLint прошли.

## 5. Недельные меню и снимки

- Реализованы несколько меню, семь дней, стандартные и пользовательские приёмы пищи.
- Поддержаны несколько рецептов, порции, дополнительные продукты, удаление и очистка приёма пищи или дня.
- Снимок рецепта создаётся backend при добавлении и содержит данные для отображения и покупок.
- Обычное редактирование меню не перезаписывает снимок, поэтому удаление, изменение или снятие оригинала с публикации не повреждает меню.

Проверки: TypeScript, ESLint и E2E-сценарий меню прошли.

## 6. Список покупок

- Расчёт вынесен в независимый backend-сервис.
- Учтены исключения дня, приёма пищи, рецепта и дополнительного продукта.
- Общие ингредиенты объединяются только по `commonIngredientId` и единице; кастомные ингредиенты и дополнительные продукты не объединяются.
- Реализованы ручное добавление, изменение, удаление, отметка покупки и явное сохранение.
- Повторный расчёт заменяет список и запрашивает подтверждение только при наличии ручных изменений.

Проверки: 6 unit-тестов расчётной логики и E2E-сценарий списка покупок прошли.
